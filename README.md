# Virtual Lab

Приложение для работы с телеметрией в Windows. Включает визуальный редактор экранов, управление по Modbus TCP, приём JSON-телеметрии и архив SQLite. Ядро написано на C++20, интерфейс использует Qt Quick.

## Запуск

Команда `./build.ps1 -Deploy` создаёт переносимую сборку `dist/Virtual-Lab/Virtual-Lab.exe`. Для переноса программы скопируйте папку сборки целиком.

1. При первом запуске в редакторе откроется пример насосной станции.
2. Нажмите **Запустить опрос**. Приложение поднимет локальный симулятор на `127.0.0.1:15020`, и на операторском экране появятся показания.
3. На экране **Управление** можно попробовать пуск, останов, тумблер, клапан, выбор режима, ввод числа, ползунок и поворотный регулятор. Кнопкой **Прервать связь** можно проверить индикацию устаревших данных и блокировку управления, а затем восстановить соединение.
4. Вкладки **Теги**, **Архив** и **События** доступны во время опроса. Для постоянного архива сохраните демопроект перед запуском опроса.
5. На экране **Приборы** доступны стрелочный циферблат, термометр, сегментное кольцо, цифровое табло, сигнальная лампа и компас. Эти элементы есть и в палитре редактора. В свойствах можно задать тег, цвет, точность и диапазон шкалы, где он применим.
6. Экран **Все элементы** показывает все 26 видов из палитры, включая линейный прибор, двигатель, трубопровод и виджет тревоги с кнопкой квитирования. Запустите опрос, чтобы увидеть их реакцию на показания симулятора.

## Язык интерфейса

Откройте **Проект → Язык интерфейса → Українська** или **Русский**. Переключение применяется сразу и сохраняется при перезапуске. В открытом проекте сохраняются настроенные названия и подписи. Чтобы посмотреть украинский пример, после переключения откройте **Проєкт → Відкрити демопроєкт**. Стандартные кнопки системных диалогов используют язык Windows.

## Просмотр архива

Включайте любые каналы галочками. В режиме **Раздельно** у каждого ряда своя шкала значений, шкала времени общая. **Сводный** накладывает все выбранные ряды друг на друга с разными цветами. На сводном графике доступны общая числовая шкала и приведение каждого ряда к 0–100% по его минимуму и максимуму в видимом интервале.

Слева видны текущие показания и значения в выбранный момент. Курсор показывает последнюю сохранённую точку на выбранное время с учётом качества данных. Наведите мышь на значение курсора, чтобы увидеть время самой записи.

Масштаб меняется колесом вокруг указателя, время сдвигается перетаскиванием. Щелчок закрепляет курсор. Метки **A** и **B** показывают длительность между двумя моментами. Кнопки **Весь архив** и **До сейчас** переключают диапазон, а **Интервал…** открывает выбор обеих дат. CSV выгружается для выбранного канала и видимого диапазона.

## Свой проект

Откройте **Источники → + Источник → JSON-телеметрия** и выберите **JSON по WebSocket** или **JSON по USB COM**. Источник ожидает протокол телеметрии v1. Меню **Теги JSON** позволяет загрузить пример, импортировать свою таблицу и выгрузить текущую. [Пример таблицы тегов](engine-tags.json)

1. Откройте **Проект → Новый проект** и добавьте Modbus TCP-подключение. Для каждого узла задайте свой IP-адрес или имя, порт, период опроса и тайм-аут.
2. Добавьте теги. Для каждого выберите источник, Unit ID, таблицу и **адрес с нуля**. Если документация контроллера обозначает первый holding-регистр как `40001`, введите адрес `0` и таблицу **Holding Registers**. Сверьте нумерацию с документацией своего устройства.
3. Укажите тип данных. Для регистров доступны UInt16, Int16, UInt32, Int32 и Float32, для битовых таблиц — Bool. Порядок байтов можно выбрать для каждого тега. Значение рассчитывается по формуле `сырое × масштаб + смещение`.
4. Во вкладке **Редактор** перетащите элемент на холст, привяжите его к тегу в правой панели и примените свойства. Элементы можно перемещать, менять размер мышкой, копировать и размещать на разных слоях. Выделите несколько элементов с Shift для выравнивания, группировки или сохранения шаблона. У экземпляра шаблона можно задать собственные теги и переходы.
5. Сохраните проект и запустите опрос. Для смены настроек устройств или тегов остановите опрос. Для архивирования задайте период записи в настройках тега.

В свойствах управляющего виджета откройте **События и действия…**. Выберите событие, например **Нажал**, **Отпустил** или **Щёлкнул**, затем задайте действие и тег. Для записи можно использовать заданное число, значение виджета или показание другого тега. Для кнопки удержания можно записывать 1 при нажатии и 0 при отпускании. Пустой список действий оставляет встроенную команду виджета.

Чтобы перенести текущие обороты в уставку, выберите **Нажал → Записать → Уставка оборотов → Из другого тега → Обороты**. Для Modbus Virtual Lab запрашивает новое показание и записывает его после успешного ответа. Для потоковой JSON-телеметрии используется последнее актуальное показание с хорошим качеством.

Запись включается отдельно в источнике и теге и доступна для **Coils** и **Holding Registers**. Действие **Прочитать** запрашивает выбранный тег Modbus TCP вне очередного цикла опроса. Несколько действий одного события добавляются в очередь сверху вниз. Действия по одному источнику выполняются в порядке очереди. Тег показания и тег обратной связи задаются отдельно.

Для тумблера и клапана выберите логический тег. В поле **Обратная связь** можно отдельно привязать фактическое состояние. Для регуляторов задайте диапазон, шаг и точность. Значение можно отправлять по кнопке **Записать** или после завершения изменения. Переключатель режимов хранит от двух до шести подписей и соответствующих числовых значений. Трубопровод можно расположить горизонтально или вертикально и связать его цвет с тегом. Для виджета тревоги порог задаётся в теге, а квитирование записывается в журнал.

У элемента **Тренд** кнопка **Ряды, шкалы и период…** открывает настройки тегов, цветов, вида линий, периода, подписей времени и легенды. В режиме **Отдельная для каждого ряда** рядом с графиком видна цветная шкала с единицами тега. Для каждой шкалы можно задать сторону, минимум, максимум и количество делений. Фон меняется в **Цвета и пороги…**.

Нажмите на период в правом верхнем углу графика или щёлкните правой кнопкой по полю, чтобы выбрать интервал либо вернуться к текущему времени. Колесо масштабирует время, перетаскивание сдвигает его, щелчок закрепляет курсор. Легенда включает и выключает ряды. Значения появляются при наведении на легенду, а в свойствах можно включить их постоянный показ.

Кнопка **Цвета и пороги…** в свойствах элемента задаёт фон, цвет показания и правила оформления. Введите пробное значение, чтобы проверить результат. Первое подходящее правило в списке имеет приоритет.

Для настройки всей мнемосхемы откройте **Редактор → Экран → Свойства экрана…**. Там задаются ширина и высота, цвет или изображение фона, шаг сетки и способ отображения. По умолчанию мнемосхема заполняет окно. **F11** показывает её на весь экран. **Esc** возвращает окно.

## Лицевые панели

Лицевая панель работает как один виджет на мнемосхеме. Её **тип** хранит макет из нескольких элементов и их интерфейсные теги. У типа может быть несколько экземпляров на одном или разных экранах. [Типы и экземпляры Faceplates в WinCC Unified](https://docs.tia.siemens.cloud/r/en-us/v21/configuring-screens-rt-unified/configuring-faceplates-rt-unified/basics-rt-unified/basics-of-faceplates-rt-unified)

В редакторе выделите элементы с **Shift**, нажмите **Создать тип из выбранных…** и задайте имя. Их текущие привязки станут интерфейсными тегами, а на экране появится первый экземпляр. Чтобы начать с пустого макета, откройте **Свои виджеты → Создать виджет…**, введите имя и размер. Для размещения следующего экземпляра выберите тип в разделе **Свои виджеты** и нажмите **Вставить**. Через **Привязки тегов…** задайте отдельные теги каждого экземпляра. В демопроекте на экране **Типовые панели** показаны два экземпляра одного типа.

На холсте своего виджета доступны картинки PNG, SVG, JPEG и BMP, прямоугольники, эллипсы, линии и все обычные виджеты. В списке **Слои** можно выбрать перекрытый элемент, поменять порядок и зафиксировать положение. Геометрия настраивается мышью или через свойства. В **Оформление и условия…** добавьте правило по тегу для смены цвета, подписи или видимости. Для состояний с разными картинками разместите их друг над другом и задайте условия их видимости. **Зона команды** принимает нажатие, отпускание и щелчок поверх изображения. Действия настраиваются в её свойствах тем же способом, что и на кнопке.

В свойствах слоя откройте **Анимация слоя…**, выберите **Вращение** или **Мигание**, затем укажите тег, условие и период полного цикла. У вращения настраивается направление, у мигания — непрозрачность тусклой фазы. Когда условие перестаёт выполняться или данные устаревают, слой возвращается в исходное положение и к полной непрозрачности.

Чтобы посмотреть готовый пример, откройте **Проект → Открыть демопроект → Свой насос**. В операторском режиме запустите опрос симулятора и нажмите **Стоп** или **Пуск**. В редакторе двойной щелчок по насосу откроет тип. Нажмите **Предпросмотр**, включите **Насос работает** и задайте уровень 65 %. Крыльчатка начнёт вращаться, а красная плашка **Высокий уровень** — мигать. Действия кнопок попадут в журнал симуляции, где можно посмотреть событие, тег и подготовленное значение.

Чтобы изменить состав, выберите экземпляр и нажмите **Открыть тип**. Команды **Интерфейс тегов…** и **Размер типа…** находятся над холстом редактора типа. Правки макета видны во всех экземплярах. Положение, размер и привязки каждого экземпляра задаются на экране.

В редакторе типа откройте **Интерфейс свойств…** и добавьте поля, которые можно настраивать отдельно у каждого экземпляра. Выберите внутренний элемент и опубликуйте его подпись, цвет подписи, фон, цвет показания или видимость. Затем выделите экземпляр на экране и откройте **Свойства экземпляра…**. Для каждого поля можно оставить значение типа или задать своё. Для фона и показания правила по порогам применяются поверх базовых цветов экземпляра. [Интерфейс свойств в WinCC Unified](https://docs.tia.siemens.cloud/r/en-us/v21/configuring-screens-rt-unified/configuring-faceplates-rt-unified/editing-faceplates-rt-unified/interface-properties-in-faceplates-rt-unified/configure-interface-property-rt-unified)

В диалоге **Свойства экземпляра…** нажмите **По тегу…** рядом с цветом или видимостью. Для каждого свойства отдельно выбирается числовой или логический тег проекта. Задайте условие и результат в поле **Если выполнено**. В поле **Иначе** можно указать отдельное значение. При ложном условии без значения **Иначе** и при недоступном числовом показании действует обычное оформление элемента.

Чтобы индикатор появлялся красным при аварии, опубликуйте его видимость и цвет. Привяжите оба свойства к одному тегу с настроенной тревогой и выберите **Авария активна**. В привязке видимости включите **Показывать** в поле **Если выполнено** и выключите **Показывать** в поле **Иначе**, включив там **Задать значение**. Для цвета при аварии выберите красный. Индикатор остаётся видимым после квитирования до снятия тревоги.

В демопроекте этот пример настроен у насоса на экране **Типовые панели**. Плашка **АВАРИЯ** появляется при тревоге тега **Уровень бака**. Для дискретного сигнала вместо тревоги можно выбрать **Равно** и указать порог **1**.

Чтобы перенести тип, нажмите **Экспорт…** в его строке в списке **Свои виджеты**. Файл `*.faceplate.json` включает виджеты, интерфейсные теги, свойства и изображения. В другом проекте нажмите **Импорт…** и выберите **Создать новый тип** с нужным именем или **Заменить существующий тип**. При замене в колонке **Поле из файла** можно выбрать соответствие вручную, если имена отличаются, или скорректировать автоматический выбор. Замена сохраняет настройки экземпляров после сопоставления всех используемых полей.

Подтверждённые сопоставления импорта сохраняются вместе с проектом. После открытия проекта при повторной замене из файла того же исходного типа редактор подставит совместимые поля.

Чтобы переключить один вставленный фейсплейс, выберите его и нажмите **Сменить тип…**. В колонке **Поле нового типа** проверьте или задайте соответствия для его привязок и настроек. После сохранения проекта редактор подставит их при следующей смене между этими типами. Смену можно отменить одной командой.

## Файлы проекта

- `Имя.scada.json` содержит настройки источников, теги, экраны, типы лицевых панелей и привязки.
- `images/` содержит добавленные изображения.
- `history.sqlite` содержит архив и журнал событий. Для переноса папки с архивом сначала закройте проект. Команда **Сохранить как** создаёт копию конфигурации с отдельной историей.

## Сборка

Чтобы продолжить разработку в новом чате Codex, откройте ту же папку проекта и начните с [HANDOFF.md](HANDOFF.md). В нём описаны текущее состояние, архитектура, форматы, протокол и сборка.

Нужны CMake, Ninja, C++20 и Qt 6.5 или новее с модулями Qt Quick, Qt Quick Controls, Qt Network, Qt WebSockets, Qt Serial Bus, Qt Serial Port, Qt SQL, Qt SVG и инструментами Qt Linguist. Скрипт по умолчанию использует Qt 6.8.3 и MinGW 13.1 из локальной папки `.toolchain`. Для внешней установки передайте `-QtRoot` и `-CompilerBin`.

```powershell
.\build.ps1
.\build.ps1 -Deploy
```

Первый вызов собирает программу и запускает тесты. Второй также создаёт переносимую папку в `dist`. GUI-проверка использует Qt offscreen и встроенный сервер на порту 15020. Тесты ядра запускают Modbus-серверы на свободных локальных портах.

Дополнительные протоколы регистрируются в `src/drivers.cpp`. Контракт `DataSource` определяет получение значений, состояние источника и подтверждение записи. Специфические для протокола параметры хранятся в `settings` и `address`, общие поля тегов используются экранами и архивом.
