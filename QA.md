# Проверка Virtual Lab

Тесты запускают приложение с отдельными пользовательскими настройками. Проекты, изображения и файлы обмена для тестов создаются во временной папке. Команды управления направляются встроенному симулятору Modbus TCP. Тест WebSocket использует локальный сервер.

## Как повторить

```powershell
.\build.ps1
ctest --test-dir build -R '^scada_ui_audit$' --output-on-failure
```

Первый запуск собирает приложение и запускает три набора. Второй отдельно повторяет проверку кнопок и файлов. Если задана переменная `SCADA_UI_CAPTURE` с путём к папке, тест интерфейса сохраняет снимки, а дополнительный сценарий сохраняет `ui-audit-failure.png` при сбое. Два сценария интерфейса используют общий порт 15020 по очереди.

## Результат

Сборка с иконкой Virtual Lab прошла все три набора CTest за 81,32 с. В EXE проверены ресурсы иконки с десятью размерами, при запуске проверено отображение в заголовке окна и на верхней панели.

После переименования в Virtual Lab сборка `build.ps1 -Deploy` прошла все три набора CTest за 72,40 с. Проверен запуск `dist/Virtual-Lab/Virtual-Lab.exe` и новое имя в заголовке окна, на верхней панели и в системных окнах открытия и сохранения проекта.

В предыдущем комплексном прогоне тест ядра занял 7,55 с, основной сценарий интерфейса — 49,22 с, проверка кнопок и файлов — 22,45 с. Дополнительный сценарий выполнил 242 нажатия по 155 различным элементам интерфейса. Основной сценарий дополняет его проверками управления, работы с данными, настроек фейсплейсов и анимации.

В предыдущем прогоне оба сценария интерфейса повторно прошли из переносимой сборки с системным `PATH` и завершились кодом 0. При завершении Qt вывел предупреждения наблюдателя временной тестовой папки. Журналы находятся в `build/portable-comprehensive-ui.stderr.log` и `build/portable-comprehensive-audit.stderr.log`.

## Исправление по результатам прогона

При опросе кнопка **Квитировать** могла потерять нажатие, потому что список тревог пересоздавался при обновлении телеметрии. Список теперь обновляется при появлении, снятии или квитировании тревоги. Тест удерживает кнопку до очередного показания Modbus и после отпускания проверяет квитирование. Тест ядра отдельно проверяет, что обычные показания не меняют список тревог.

## Границы проверки

Проверки протоколов используют программные симуляторы. Физический ПЛК, подключённое USB COM-устройство и внешний сетевой стенд требуют отдельного прогона. В предупреждении Windows о перезаписи вручную проверен отказ. Повторяющиеся строки используют те же обработчики, поэтому сценарии проверяют выбранные строки и граничные случаи.
